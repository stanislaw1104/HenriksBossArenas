# Архитектура

## Текущий статус

Реализованы загрузочная точка и минимальный серверный каркас первого сценария Desert Scourge: обнаружение NPC Calamity, одна сессия, временная арена, перенос игроков, возврат после победы и восстановление тайлов. До ручного прогона в tModLoader этот сценарий считается прототипом, а не подтверждённой мультиплеерной функцией.

## Базовые ограничения будущей архитектуры

- Calamity Mod — обязательная сильная зависимость.
- Состояние будущего боя должно управляться сервером и синхронизироваться с клиентами.
- Решение обязано поддерживать выделенный сервер и безопасно обрабатывать повторные события, подключения, отключения, смерть и возрождение игроков.
- Архитектура арен будет выбрана только после отдельного исследования возможностей tModLoader и совместимости с Calamity.

## Архитектурное решение, ожидающее утверждения

Базовый вариант — временная арена в безопасной области природной пустыни основного мира. Для каждой сессии система сохраняет снимок изменяемого прямоугольника, строит арену на сервере, синхронизирует изменённые участки и восстанавливает снимок после победы или перед штатным сохранением мира.

Subworld-механика не является нативной возможностью tModLoader; она реализуется внешней Subworld Library через внедрения и дополнительные subserver-процессы. Поэтому она не станет базовой зависимостью до отдельного доказанного прототипа. Полный анализ: [ARCHITECTURE_RESEARCH.md](ARCHITECTURE_RESEARCH.md).
